= 소개

이 워크숍은 Red Hat OpenShift AI 3.5에서 AI 모델 추론을 배포하고 테스트하는 실습 가이드입니다. 모델 카탈로그에서 모델을 배포하고, 계층화된 접근이 가능한 Models-as-a-Service(MaaS)를 구성한 후, 채팅 인터페이스를 연결하여 엔드투엔드 추론을 테스트합니다. 마지막으로 Playground에서 MCP 서버를 도구로 연결해 에이전트 방식의 추론까지 확인합니다.

[TIP]
====
스크립트를 이용한 환경 설정(MaaS 게이트웨이, Operator, 대시보드 기능, DevSpaces 등)은 https://github.com/jingggg-wenn/rhoai-sno-setup-guide[RHOAI 3.5 SNO Setup Guide]를 참고하십시오. 두 개의 스크립트로 클러스터 준비 과정 전체를 자동화할 수 있습니다.
====

== 학습 목표

이 워크숍을 완료하면 다음을 수행할 수 있습니다.

* OpenShift AI에서 Data Science 프로젝트를 생성합니다
* 모델 카탈로그에서 llm-d 서빙 런타임을 사용하여 AI 모델을 배포합니다
* 자체 호스팅 채팅 인터페이스인 Open WebUI를 배포합니다
* 서로 다른 토큰 속도 제한(Premium 및 Basic 등급)으로 MaaS 구독을 구성합니다
* 인증된 모델 접근을 위한 API 키를 생성합니다
* MaaS 게이트웨이를 통해 Open WebUI를 모델에 연결하고 채팅 기반 추론을 테스트합니다
* Playground에서 모델에 MCP 서버를 연결하고 도구 호출 기반의 추론을 테스트합니다

== 사전 요구 사항

시작하기 전에 다음 사항을 확인하십시오.

* Red Hat OpenShift AI 3.5가 설치된 OpenShift 클러스터가 실행 중이어야 합니다
* 클러스터에 GPU 노드가 하나 이상 있어야 합니다(예: NVIDIA L4, L40S, A100)
* 관리자가 GPU Hardware Profile을 생성해 두어야 합니다
* 관리자가 MaaS와 실습용 MCP 서버를 미리 구성해 두어야 합니다
* 강사가 제공한 로그인 정보(사용자명과 비밀번호)가 준비되어 있어야 합니다

== 사용자 계정 안내

이 가이드에서는 ``user-XX``, ``admin-XX``와 같은 형식을 사용합니다. ``XX``를 배정받은 번호로 바꿔서 사용하십시오. 번호는 항상 두 자리로 씁니다.

예를 들어 **5번**을 배정받은 경우 다음과 같습니다.

[cols="1,1",options="header"]
|===
| 항목 | 값

| 로그인 사용자명
| `user05`

| 프로젝트(네임스페이스) 이름
| `user-05`
|===

관리자 계정도 같은 방식입니다. 예를 들어 ``admin02``로 로그인한 경우 프로젝트 이름은 ``admin-02``입니다.

= Models-as-a-Service (MaaS) 설정

이 모듈에서는 모듈 3에서 배포한 모델에 대해 Models-as-a-Service(MaaS)를 구성합니다. MaaS는 인증, 속도 제한, 사용량 추적 기능을 갖춘 중앙 집중식 API 게이트웨이를 제공하며, 상용 AI 제공 업체가 모델을 노출하는 방식과 유사합니다.

이 모듈을 완료하면 다음을 갖추게 됩니다:

* 모델 접근을 제어하는 MaaS 구독
* 인증된 추론 요청을 위한 API 키(``sk-oai-*``)
* 클러스터 외부에서 접근 가능한 검증된 외부 엔드포인트

== MaaS의 필요성

``LLMInferenceService``(llm-d)로 모델을 배포하고 MaaS로 게시하면, 모델은 직접 경로가 아닌 MaaS 게이트웨이를 통해 노출됩니다. 이를 통해 다음 기능이 제공됩니다.

* **인증**: API 키 또는 OpenShift 토큰이 있어야 접근할 수 있습니다.
* **속도 제한**: 구독별로 토큰 기반 할당량을 적용합니다.
* **사용량 추적**: 토큰 소비량을 한곳에서 확인할 수 있습니다.
* **멀티테넌트 접근**: 여러 팀이 서로 다른 할당량으로 동일한 모델을 공유할 수 있습니다.

== 단계 5.1: 모델 준비 상태 확인

MaaS를 설정하기 전에 모듈 3에서 배포한 모델이 실행 중인지 확인합니다.

외부 URL은 다음 형식을 따릅니다.

[source,text]
----
https://maas.apps.<cluster-domain>/<namespace>/<model-name>/v1
----

*방법 A: 대시보드 UI*

. OpenShift AI 대시보드에서 **AI hub** > **Models** > **Deployments**로 이동합니다.
. 본인의 프로젝트를 선택하고 모델 상태가 **Ready**(녹색)인지 확인합니다.
. 모델 옆의 **Internal and external endpoint**를 클릭하여 **External API endpoint** URL이 표시되는지 확인합니다.
+
image::maas-setup/img-maas-endpoints-0.png[모델의 External API endpoint URL]

*방법 B: Web Terminal*

. OpenShift Console 우측 상단의 **>_** 아이콘을 클릭하여 Web Terminal을 엽니다.
. 다음 명령어를 실행합니다. 모듈 4에서 설정한 ``NAMESPACE`` 변수를 사용합니다. 터미널을 새로 열었다면 ``export NAMESPACE=user-XX``를 먼저 실행합니다(``user-XX``는 본인의 네임스페이스로 변경).
+
[source,bash]
----
oc get llminferenceservice -n $NAMESPACE -o jsonpath='{.items[0].status.url}{"\n"}'
----
+
다음과 같이 모델의 External API endpoint URL이 출력됩니다. 출력된 URL에는 ``/v1``이 포함되어 있지 않으므로, 모듈 6에서 사용할 때 끝에 ``/v1``을 붙입니다.
+
image::maas-setup/img-maas-endpoints-3.png[Web Terminal에서 조회한 모델 URL]

== 단계 5.2: MaaS 구독 생성 (관리자)

구독은 어떤 그룹이 어떤 모델에 접근할 수 있는지 정의하고 토큰 속도 제한을 설정합니다. 계층화된 접근을 시뮬레이션하기 위해 서로 다른 속도 제한을 가진 두 개의 구독을 생성합니다.

[cols="1,1,1,1",options="header"]
|===
| 구독 | 우선순위 | 토큰 속도 제한 | 사용 사례

| `workshop-gemma4-premium`
| `20`
| `10000` 토큰 / `1` 분
| 높은 처리량 사용자 (예: 운영 워크로드)

| `workshop-gemma4-basic`
| `10`
| `100` 토큰 / `1` 분
| 일반 사용자 (예: 워크숍 참가자)
|===

사용자가 여러 그룹에 속해 있을 때는 우선순위가 높은 구독이 기본으로 적용됩니다.

=== Premium 구독 생성

. OpenShift AI 대시보드에서 **Settings** > **MaaS governance**로 이동합니다.
+
image::maas-setup/img-maas-governance.png[Subscriptions 탭이 표시된 MaaS governance 페이지]

. **Create subscription**을 클릭하고 양식을 작성합니다.
+
[cols="1,2",options="header"]
|===
| 필드 | 값

| **Name**
| `workshop-gemma4-premium`

| **Priority**
| `20`

| **Groups**
| `rhods-admins` 선택 (또는 강사가 제공한 그룹)

| **Models**
| **Add models**를 클릭하여 배포된 모델을 선택합니다

| **Token rate limits**
| `10000` 토큰 / `1` 분

| **Create authorization policy**
| 선택된 상태로 유지합니다
|===
+
image::maas-setup/img-maas-subs-1.png[이름, 우선순위, 그룹이 입력된 구독 생성 양식]

. **Add models**를 클릭하여 모델 선택 대화 상자를 엽니다. 관리자 권한으로 다른 네임스페이스에 배포된 모델이 함께 표시될 수 있습니다. 반드시 본인의 네임스페이스(``user-XX``)에 배포된 모델을 선택한 후 **Add models**를 클릭합니다.
+
image::maas-setup/img-maas-subs-2.png[배포된 모델이 표시된 모델 추가 대화 상자]

. 모델을 추가한 후, 모델 항목 옆의 **Add token limit**를 클릭합니다.
+
image::maas-setup/img-maas-subs-3.png[Add token limit이 표시된 추가된 모델]

. 토큰 제한을 `10000` 토큰 / `1` 분으로 설정하고 **Save**를 클릭합니다.
+
image::maas-setup/img-maas-subs-4.png[구독 토큰 제한 편집 대화 상자]

. **Create authorization policy**가 선택되어 있는지 확인하고 **Create subscription**을 클릭합니다.
+
image::maas-setup/img-maas-subs-5.png[제출 준비가 완료된 구독 양식]

=== Basic 구독 생성

위와 동일한 단계를 반복하되, 다음 값으로 두 번째 구독을 생성합니다.

[cols="1,2",options="header"]
|===
| 필드 | 값

| **Name**
| `workshop-gemma4-basic`

| **Priority**
| `10`

| **Groups**
| `rhods-admins` 선택 (또는 Premium과 동일한 그룹)

| **Models**
| Premium과 동일한 배포된 모델을 선택합니다

| **Token rate limits**
| `100` 토큰 / `1` 분

| **Create authorization policy**
| 선택된 상태로 유지합니다
|===

image::maas-setup/img-maas-subs-basic.png[이름, 우선순위, 그룹, 모델, 토큰 제한이 입력된 Basic 구독 양식]

두 구독을 모두 생성하면 **Subscriptions** 탭에 ``workshop-gemma4-premium``과 ``workshop-gemma4-basic`` 두 항목이 모두 **Ready** 상태로 표시되어야 합니다.

image::maas-setup/img-maas-subs-6.png[Premium과 Basic이 모두 Ready 상태로 표시된 Subscriptions 탭]

**Authorization policies** 탭을 클릭하여 두 구독에 대한 정책이 생성되었는지 확인합니다.

image::maas-setup/img-maas-subs-7.png[두 구독에 대해 생성된 Authorization policies]

== 단계 5.3: API 키 생성

구독마다 API 키를 하나씩, 모두 두 개 생성합니다. 모듈 6에서 이 키들을 사용해 Open WebUI에서 속도 제한의 차이를 테스트합니다.

=== Premium API 키 생성

. **Gen AI studio** > **API keys**로 이동합니다.
+
image::maas-setup/img-apikey-1.png[Gen AI studio API keys 페이지]

. **Create API key**를 클릭하고 양식을 작성합니다.
+
[cols="1,2",options="header"]
|===
| 필드 | 값

| **Name**
| `apikey-premium`

| **Subscription**
| `workshop-gemma4-premium` 선택

| **Expiration**
| `30 days`
|===
+
image::maas-setup/img-apikey-2.png[이름, 구독, 만료 기간이 입력된 API 키 생성 대화 상자]

. **Create API key**를 클릭합니다.

. 생성된 API 키를 복사 아이콘을 사용하여 즉시 복사합니다. 키는 ``sk-oai-``로 시작하며 한 번만 표시됩니다.
+
image::maas-setup/img-apikey-3.png[생성된 키가 표시된 API 키 생성 완료 대화 상자]

IMPORTANT: 이 API 키를 안전하게 저장하십시오. 이 대화 상자를 닫은 후에는 다시 확인할 수 없습니다.

=== Basic API 키 생성

동일한 단계를 반복하여 두 번째 API 키를 생성합니다.

[cols="1,2",options="header"]
|===
| 필드 | 값

| **Name**
| `apikey-basic`

| **Subscription**
| `workshop-gemma4-basic` 선택

| **Expiration**
| `30 days`
|===

image::maas-setup/img-apikey-4.png[Basic 구독에 대한 API 키 생성 대화 상자]

이 키도 복사하여 저장합니다. 이제 서로 다른 속도 제한을 가진 두 개의 API 키가 준비되었으며, 모듈 6에서 Open WebUI에 연결하는 데 사용합니다.
